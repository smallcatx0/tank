## 方案与决策记录

### 已明确确认的决策

1. 请求标识使用 `x-b3-traceid`，严格校验格式，不兼容旧 `request_id` 请求头。
2. 店铺示例补齐真实创建与查询。业务报错保持简洁；普通系统错误按环境区分，具体规则见下方响应方案。

### 请求标识契约

- 接受非全零的 16/32 位十六进制输入，规范化为小写；缺失或非法时生成新的 32 位标识，不因此拒绝业务请求。
- 响应头 `x-b3-traceid`、响应体 `request_id` 和日志 `trace_id` 使用同一值。
- 同时写入 Gin 上下文与标准请求 context，独立内部职责包提供 context 存取能力，模型层不引用 HTTP 中间件。
- 修正装配测试、注释和接入说明。本批不引入完整下游分布式追踪。

### 安全响应与日志方案

- 保留 `env == dev` 时普通系统错误的内部错误回显：HTTP 状态码为 500、业务码为 50000，msg 使用 err.Error()，包括已有包装上下文，满足开发联调定位需要，不统一替换为“服务错误”。SQL、下游地址等调试上下文可以随错误信息返回；密码、token 等敏感字段仍按规范在构造错误前脱敏。
- 非 dev 环境对普通系统错误统一返回 `500 / 50000 / 服务错误`，不暴露内部实现细节。此环境差异仅针对普通系统错误；业务错误和 panic 恢复沿用各自契约，本批不新增向响应注入堆栈的机制。
- 参数错误使用简短可操作的提示，如“店铺名称不能为空”“店铺状态无效”；无法安全定位字段的绑定错误使用“请求参数无效”。业务错误只携带可公开文案和数据。
- 业务操作超时返回 `504 / 50400 / 请求处理超时`，客户端已取消时停止后续工作，不再尝试正常成功响应。
- 日志记录操作名、错误类别、trace_id、经白名单筛选且脱敏的业务参数和 ID；不直接输出任意第三方错误原文。已知错误提取安全字段，未知错误保留类型和操作上下文。
- 将 ReqLog 改为请求完成日志，记录 method、路由模板、status、latency_ms、trace_id；不读取或记录请求体，不记录完整查询串、Authorization、Cookie 等。
- 检查 GORM 日志适配器，避免 SQL 调试日志绕过安全边界。已发生的系统错误和 panic 仍须保留必要的安全定位信息，不以“报错简洁”为由吞掉故障。

### 数据库上下文与超时方案

- 从 `c.Request.Context()` 派生操作期限；创建与查询固定使用 time.Second，不提供店铺超时配置。
- 模型方法显式接收 context 与数据库实例，数据库调用使用 WithContext。
- 列表 Count 与 Find 共享同一次期限；父 context 更短时服从父期限。
- 客户端取消或操作超时后停止后续查询，释放取消函数与连接资源；错误链保留 errors.Is 判断能力。
- 创建超时不自动重试；超时不保证未提交，避免示范出重复写入行为。

### 店铺示例方案

- 保留创建、列表路径及参数；创建真实写库并返回店铺 ID 等必要数据，替代 demo/validated。
- 列表支持状态筛选、按 id DESC 排序；空列表返回 []；保留分页归一规则，不承诺并发写入下 Count 与列表的快照一致性。
- 表模型依照规范放在 models/dao/schema（package schema）；数据访问方法显式接收依赖，按用户明确要求，控制器直接读取 global.MysqlCli 并显式传给模型，模型仍不读取全局连接。
- 提供显式执行的建表 SQL，不在服务启动时自动迁移；此阶段不新增 service 层。
- 店铺作为完整示例，创建与列表路由默认注册并开启，沿用现有路径；无需额外启用配置，本批不新增示例路由开关。此项已由用户明确确认。

### 实施决策

- 保留现有 internal/resp 包名，不在本批扩大重命名范围；按用户确认，schema 为 GORM 模型定义包，店铺模型及相关数据方法统一放在 models/dao/schema。
- 路由入口直接注册空结构体 Shop 的处理方法；原有店铺路径默认注册，不增加开关。
- 独立 internal/requestctx 承载请求信息，internal/errinfo 提取安全诊断字段；GORM 日志不调用 SQL 格式化回调。
- dev 普通系统错误继续返回完整 err.Error() 包装上下文，非 dev 使用安全提示。日志两种环境均仅输出安全字段。
- 接入指南在工作区已移至根目录，本批在现位置更新，修正相对链接；保留工作区原有的旧文档及历史文件删除状态。计划中的旧条目清理由外部编辑产生，本批仅维护 D19 条目。

### 封装精简

- 删除 routes.NewShopHandler；后续按用户要求同步删除 NewShop，路由直接注册 Shop{}。
- 删除 newSQLLogger，DAO 内直接构造 sqlLogger，日志等级与安全适配行为保持一致。
- 删除 ShopQuery；ListShops(ctx, db, status, page) 显式接收筛选条件与分页输入输出对象。
- 移除不使用接收者的 Shop.List，采用上述包函数；使用接收者实际数据的 Shop.Create 保留。
- 用户进一步确认：数据库直接使用 global.MysqlCli，创建和查询固定 1 秒。删除 Shop 的 db/timeout 字段、NewShop、ShopTimeout 配置字段、shop.operation_timeout 示例及配置测试；标准请求 context 取消传播不变。

- 测试在串行用例中设置全局数据库，并通过 t.Cleanup 恢复原值；不并行改写全局依赖。固定 1 秒操作期限及较短父期限分别验证。
