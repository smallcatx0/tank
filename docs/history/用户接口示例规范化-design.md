# 用户接口示例规范化

## 问题

用户要求修复用户 demo 的校验、敏感数据回传、身份来源、错误透传和列表语义问题，并补测试。

## 规则与约束

遵循 [仓库协议](../../AGENTS.md) 和 [项目规范](../../项目规范.md)。

## 方案与决策记录

- 保留简洁控制器，不注册生产路由；手机号使用内置 e164 配合 startswith=+，示例 +8613800138000。测试确认单独 e164 接受无加号数字，因此额外约束前缀。
- 身份仅来自鉴权中间件写入 AuthenticatedUserIDKey 的非空字符串，仓库尚无真实鉴权实现。
- 自定义校验改为 Valid() error，删除请求 DTO 的身份字段。业务授权及唯一性留在业务层。
- 绑定失败返回固定提示，区分 JSON 和查询参数，不透传底层错误。
- 创建返回 demo/validated 标识，不实际创建、不回传输入；列表返回 demo 标识、分页和空列表。筛选可选，分页默认 1/10，limit 上限沿用 1000，page 上限 1000000 防止偏移溢出。
- 添加 HTTP 请求级测试及校验单元测试，覆盖失败、敏感字段、边界、并发。
